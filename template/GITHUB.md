# GITHUB.md — 週六「GitHub 寶藏專案」系列

> **出片日：每週六**（由 `heartbeat.ps1` 依 `AYUAN_GITHUB_DAY` 判斷，預設 Saturday；金主 2026-10-24 訂）。
> 被心跳告知「今天是 GitHub 日」時，**先讀完這份，再開始選題**。今天不用 MEMORY.md 的一般待發題庫。
> 格式：直式 Shorts（60~90 秒、字卡 4~6 張），插圖照 `ILLUST.md`（阿遠親自示範在用這個工具）。

## 定位
每週介紹一個 **GitHub 上 1000 顆星以上**的開源專案，用白話講「它能幫一般人做什麼」。
受眾跟頻道一樣是想把 AI 用得更好的一般人／上班族，**不是工程師**——不講程式碼細節，講用途與怎麼開始。

## 選題規則（硬性）
1. **星數 ≥ 1000，而且要用工具即時查證**，不可憑印象報數字：
   ```powershell
   python pipeline\github_repo.py search [關鍵字]     # 找候選（已自動排除介紹過的）
   python pipeline\github_repo.py check owner/repo    # 定案前必跑，最後一行要是 OK
   ```
   `check` 回 `DENY` 就換一個，不要硬上。它會擋掉：已介紹過、未達 1000 星、封存、超過一年沒更新、fork。
2. **不重複**：已介紹清單在本檔最下面，`github_repo.py` 會自動比對；發完一定要補一行。
3. **優先順序**：
   ① 跟 AI 有關、一般人裝得起來或有網頁版能直接用的（本地跑模型、AI 寫作／繪圖／語音／翻譯、提示詞資源、AI 助手）
   ② 一般人用得到的實用工具（下載、筆記、檔案轉換、隱私、效率）
   ③ 純開發者框架／函式庫 → **盡量避開**，觀眾聽不懂也用不到
4. **避開**：星數暴衝但很新、說明空泛、沒有 README 或官網的專案（可能是刷星）；涉及破解、盜版、繞過付費、駭客攻擊、成人內容的專案。
5. 選題靈感可用：`search topic:llm`、`search topic:ai`、`search ai tool`、`search chatgpt`、`search whisper`、`search stable-diffusion`、`search self-hosted`。

## 查資料（講的內容要有根據）
- 用 `check` 印出的說明、官網，再上網讀它的 **README／官網**，確認功能後才寫。**不要講 README 沒寫的功能**。
- **不要在本機安裝或執行該專案**（安全考量，也不需要）——只讀說明。
- 授權：開源 ≠ 隨便商用。`check` 有印授權別，若是「無授權聲明」就不要說「可以免費商用」。

## 腳本型態（沿用高留存 5 段式）
1. **痛點鉤子**：一般人遇到的麻煩（「每次開會錄音都要自己打逐字稿？」）
2. **它是什麼**：一句話介紹＋「GitHub 上 X 萬顆星」（數字照 check 結果、四捨五入念，例：18 萬 4 千顆星）
3. **能幫你做什麼**：2~3 個具體用途，用生活例子講
4. **怎麼開始＋注意事項**：有網頁版／安裝包就講最簡單的入口；提醒「從官方 GitHub 或官網下載，別抓來路不明的版本」；有使用限制要講
5. **收尾**：一句話記憶點＋催訂閱「每週六介紹一個 GitHub 寶藏」

- 念英文專案名時照頻道既有規則（字母逐一拆開念或用常見念法，配音才不會念錯）。
- 字卡**不要放專案 logo**、插圖**不要畫 logo 或介面文字**（模型會畫錯）；讓阿遠演出「用了這個工具之後」的情境。

## 標題與 SEO
- 標題範例：《GitHub 18 萬星的 Ollama：在自己電腦跑 A I，不用連網也不用付月費 #Shorts》
- 描述第一行放專案官方網址（`check` 印的網址），並加：`#GitHub #開源 #AI工具 #Shorts`
- 播放清單：**「GitHub 寶藏專案」**（`python pipeline\add_to_playlist.py <影片ID> "GitHub 寶藏專案"`，找不到會自動建立）
- 不放進「AI 名詞白話系列」。
